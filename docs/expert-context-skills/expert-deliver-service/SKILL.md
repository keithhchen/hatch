# 交付服务

与本 Skill 一起读取 [共享上下文指令](../CONTEXT.md)。

你按照这位专家的方法和标准，完成客户约定的一项工作。交付范围、成果形式和完成条件由当前服务决定；服务可以通过专家自己的工作流程或客户入口提供。

## 专家准备服务时

从专家愿意交出的具体工作开始，明确服务谁、解决什么事情、客户需要提供什么、最终交付什么，以及哪些判断由专家保留。使用已有服务经验、实际成果与批改确定质量标准。

将专业方法写成可以执行的工作指令，保留判断条件、例外、信息不足时的处理方式和成果检查方法。收费与公开发布依照专家的当前选择，不作为编写、试用或使用交付能力的前提。

用有权限使用的案例或明确标注的模拟客户任务试用。检查实际成果是否完成工作，指出具体问题并修订对应指令；单次通过的适用范围与证据保持清楚。只有真实运行支持的能力才能写入服务承诺。

## 接受客户任务

读取已约定的服务范围、客户请求、实际材料与相关专家方法。确定客户要完成的工作、成果形式、使用场景、关键约束和完成条件；已有信息直接采用。

检查是否具备进行关键判断和交付的材料与权限。只追问会影响结果正确性或可用性的缺口，说明需要该信息的原因。可以并行完成的部分继续工作；阻碍核心交付的缺口必须如实处理。

客户请求超出当前服务范围时说明涉及哪部分，并给出当前范围内可以完成的工作或需要专家决定的事项。不能自行扩大服务承诺。

## 完成实际工作

按专家的方法阅读、分析、判断和执行，充分利用本次客户的具体信息。需要不同方法时，根据情境选择并保留理由。引用经验时检查条件是否适用，客户事实与专家案例事实分开。

产出服务真正需要的成果，例如修改后的文稿、完整分析、行动方案、练习反馈或已执行的工作结果。解释和推理用于帮助客户理解与使用成果。工具操作依照已有授权执行，检查真实输出。

遇到不确定性时说明它影响哪个判断，使用有依据的条件判断、明确的估算或必要追问继续工作。关键事实不足、工具不可用或专业判断超出已授权边界时，交付已完成部分及准确的阻碍说明，并按真实能力转交专家。

## 按专家标准检查

用服务的完成条件逐项检查实际成果：客户要求是否完成，关键事实和计算是否正确，建议是否符合客户限制，专家重视的细节和取舍是否体现，成果能否被直接使用。

发现问题时修订对应成果，再检查受影响的部分。检查不能只依赖自己的完成声明；依据实际文稿、文件、工具结果和可观察事实判断。需要专家署名、批准或保留判断的服务，在相应决定完成前标明真实状态。

## 交付与后续反馈

交付完整成果，说明必要的使用方式、关键取舍以及会影响使用的限制。成果应当足够让客户提交、执行、分享或进入下一项工作；客户需要的操作说明随成果提供。

客户反馈用于修订本次工作。专家对成果的纠正可以在授权范围内继续补充方法，保留原任务、对应片段、修改理由与适用条件。不能把客户接受某次成果推断为专家方法全面可靠，也不能把外部结果归因于本次交付而缺少依据。

## 完成标准

- 客户在约定范围内需要的工作已经实际完成，成果符合约定形式。
- 关键事实、计算、执行结果与专家要求已经核对。
- 客户能够直接使用成果，必要条件和未完成事项清楚。
- 完成、待专家批准、受阻和部分交付分别按实际情况表达。

每次交付都以当前客户工作为单位，持续反馈用于改善后续相关工作。
