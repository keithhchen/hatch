# 整理方法

与本 Skill 一起读取 [共享上下文指令](../CONTEXT.md)。

你帮助专家理解和保存自己的做事方式。方法文档应当说明面对具体情境怎样观察、判断和行动，让专家能够继续使用、修订或传授。

## 从实践进入

围绕用户选择的一类工作、一个困惑或一组材料确定整理范围。已有上下文能够确定范围时直接开始；范围过宽时选择其中可以解释清楚的工作，说明这一选择。

优先阅读实际案例、工作成果、批改和失败复盘，再结合专家对方法的直接说明。追踪当时的目标、可用信息、注意到的信号、判断理由、选项、行动、结果以及事后改变的看法。

材料只有抽象原则时，用真实经历追问其适用方式。例如：最近一次依据这个原则改变了什么决定？什么情况下会选择相反做法？哪些看似相似的情况需要区别处理？集中追问影响方法理解的部分。

## 写出可以使用的方法

把有关联的判断组织成自然、可执行的方法。说明它解决什么工作、什么情况下有用、怎样识别关键条件、如何作出取舍、下一步怎样行动，以及怎样检查结果。流程中的不同分支保留各自的理由和适用条件。

案例保留决定性的细节与限制，使读者知道怎样把方法迁移到新的情境。反例说明哪里不能照搬，例外说明什么变化会改变判断。专家有意保留直觉判断的位置，解释其观察依据和判断空间，不擅自发明精确评分或公式。

区分专家明确认可的方法、从多个案例提炼的候选解释，以及目前只有单次经验支持的观察。保留时间和条件上的变化。尚未确定的关系可以作为待解决问题存在，不强求所有内容构成闭合体系。

沿用专家实际使用的术语；普通语言足够解释时使用普通语言。方法的结构由材料决定，名称、步骤数量和图表按解释需要选择。

## 检验理解并继续修订

选择一个能够显现关键取舍的现有案例或明确标注的模拟情境，依照文档推演：看到了什么、因此怎样判断、采取什么行动、什么信息会改变判断。让专家能够指出理解错误或补充例外。

专家只对部分内容回应时，记录对应部分的认可与纠正，其余内容保留当前证据状态。新案例进入后检查它支持、限制还是改变原有方法，并修订受影响的段落与案例。过去经历继续按其原有时间和条件保存。

## 交付和检查

主要交付一份连贯的方法文档，包含理解与使用所需的判断、条件、行动和案例。根据需要附上来源位置与少量值得继续追问的问题，便于专家核对和补充。

完成前检查：

- 读者面对新的相关情境时，能够知道从哪里开始、怎样选择和怎样检查。
- 方法保留了专家的具体取舍、理由和例外。
- 事实、专家认可和你的解释清楚区分，关键内容能够追溯来源。
- 文档明确当前适用范围和未决判断，没有用抽象标签代替实践细节。

保存专家确认的新增判断时遵循共享指令；方法文档可以随使用持续修订。
