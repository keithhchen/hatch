## 2026-09-09 draft implementation checkpoint

- Added native draft files keyed by a hash of account ID + conversation ID, outside Runner-readable attachments. Writes use atomic replacement and file sync; corrupt drafts produce an error, not an empty fallback.
- A native in-memory lease gives one window edit ownership per draft. Window destruction releases ownership; a stale lease cannot write or release a new owner's draft. This is a draft editor lock, not a second message-history authority.
- Renderer serializes conversation transitions, flushes the old draft before releasing ownership, restores text and attachment references, and preserves failed saves for retry. Ordinary window close waits for pending imports and draft save; installed-product quit/crash behavior still requires UAT.
- Added native clipboard import to the same durable attachment store. Picker/paste preparation stays with the initiating draft, even while switching conversation. Attachments beyond the eight-file limit now fail explicitly instead of evicting existing chips.
- Removed composer text from window-context restoration. Draft files are the sole durable composer authority.
- UI states: loading (editor disabled), ready (editable), saving (editable; sending awaits save), save error (content retained + retry), editor occupied/load error (disabled + retry). Existing components and localization are reused; no new motion or dependency.
- Added command registration, generated permissions and main/conversation-window capabilities; auxiliary windows do not receive draft commands.
- Captures a text edit version so a send cannot clear text typed during preparation, including retyping the same string. Attachment clearing targets only submitted IDs. This is not yet the accepted-message/outbox cutover.
