# Creator Agent Factory · end-to-end proof

This proof separates three questions that should not be collapsed into one
green badge:

1. Did raw Creator material become a traceable Agent package?
2. Does the Agent behave differently from a clean generic baseline?
3. Can the existing Hatch Runtime resolve and execute that exact package?

## Primary Release

- Release: `signal-resume-review@1.0.0`
- Digest: `sha256:d806cf915b29fa952e43ab4aaf02431cc39dfdde6a29b0d20509a07562eaaec5`
- Raw input: nine Creator-supplied course, PDF, video/transcript, text, and
  prior-work documents plus one natural-language intent.
- Distillation: 42 source facts, nine composed rules, explicit omissions and
  boundaries, eight synthetic QA expansions, four held-out Evals, 42 RAG
  chunks, a protected Skill, method model, and compiled system prompt.
- Source gate: every quoted source fact occurs in the extracted raw corpus;
  synthetic expansion is labelled and never promoted to Creator-authored fact.

## Semantic result versus a clean baseline

The candidate answers in `review/candidate-outputs.json` were generated by a
live OpenAI-compatible provider from the immutable Release and
`held-out-inputs.json`. Expected answers and observable checks were not exposed.

The baseline in `review/baseline-results.json` came from a clean isolated agent
that read only the same input-only holdouts—no Release, repository, expected
answers, or checks.

After blind A/B judging and a strict audit of citations that did not logically
satisfy their checks:

- Creator Agent: **16/18 (88.9%)**
- Generic baseline: **10/18 (55.6%)**
- Delta: **+33.3 percentage points**
- Semantic gate: **PASS** (at least 80%, and strictly above baseline)

`review/release-review.md` shows every actual probe, both unedited answers, and
every pass/fail. `review/blind-judge-results.json` and
`review/strict-evidence-corrections.json` preserve how the final score was
reached rather than hiding judge mistakes.

## Runtime mechanics bound to the same digest

`review/runtime-results.json` ran all four candidate answers through the
existing Hatch Runtime using the exact Release ID and digest above. The Runtime:

- resolved and re-hashed the Release;
- checked entitlement binding;
- sent the protected Skill to the worker;
- emitted `skill.run` and terminal completion events for all four probes;
- delivered exactly the independently generated semantic answers.

This run uses a deterministic ChatCompletions replay adapter. It proves Runtime
materialization and mechanics; it does **not** pretend that replay is a live
semantic model call. The live provider semantic run is recorded separately in
`candidate-outputs.json`.

## Output boundary

Only this subtree is deployable:

```text
release/<release-id>/<digest>/
  public.json
  private.json
  skills/<product-id>/SKILL.md
  skills/<product-id>/references/method-model.json
  rag/chunks.json
  rag/documents.json
```

`review/` and `work/` are Factory-side evidence, not Agent assets. The verifier
now rejects any undeclared file inside a Release. Both Releases below have zero
missing and zero unexpected files.

## Cross-domain portability

The second scenario starts from four raw strength-planning/prior-work files and
one natural-language intent under `fixtures/creator-factory/ari-strength-raw/`.
There is no Creator-authored JSON. An isolated semantic distillation produced
15 source facts, eight composed rules, eight synthetic QA expansions, four
held-outs, and 15 RAG chunks. Re-running intake and the same Factory code from
those raw files reproduced:

- Release: `ari-seven-day-strength-plan@1.0.0`
- Digest: `sha256:78aecc55083ce942e69d70dd94d8cbfd622e5843a64c8c0cdf56b5b518d68c9c`

`work/reports/portability-audit.json` proves:

- both Releases use contract version 1;
- their normalized file shapes are identical;
- their public, private, and RAG content hashes are all different;
- production Factory scripts/contracts contain neither scenario's identifying
  strings;
- neither raw input folder contains JSON or a product schema.

This is structural isomorphism with independent content—not a renamed copy of
the first Agent.

## Remaining limitations

- Semantic distillation is intentionally a Codex Skill/workflow, not yet a
  self-serve Creator product. The internal source manifest and factory plan are
  generated compiler inputs, not Creator inputs.
- Live semantic generation and Runtime mechanics are proven separately. A live
  provider call through every Runtime worker/tool hop is not claimed by this
  proof.
- External API/tool selection is represented by generic Release bindings, but
  this proof only exercises the local tool envelope.
- Automatic media transcription depends on the local extraction capability or
  a supplied transcript; the intake report records which path was used.

No remaining Creator- or domain-specific branch was found in Factory production
code, Release contracts, or Runtime-facing output shape.
